# 一、前言

飞书是字节跳动推出的企业协作平台，拥有庞大的企业用户群体。通过将 OpenClaw 接入飞书，你可以：

- 在飞书单聊中与 AI 助手对话

但是，很可能会安装失败，如下图：

![](assets/05-%E6%8E%A5%E5%85%A5%E9%A3%9E%E4%B9%A6%EF%BC%9A%E8%AF%A6%E7%BB%86%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97_Oc0Zb16ISo.jpg)

这可能是 openclaw 有一个 bug，原因是：

飞书插件的 package.json 中使用了 monorepo 的 workspace 协议：

```
"devDependencies": {
    "openclaw": "workspace:*"
}
```

当插件被下载到 ~/.openclaw/extensions/feishu/ 独立安装时，npm 不认识 workspace:* 这种协议，导致安装失败

解决步骤是：

到 [【飞书文档】可复制及下载素材 ](https://lightship-rpa.feishu.cn/docx/UTl9dHblRohKrWxt5oycRPn1nyb?from=from_copylink)文档内下载对应系统的修复脚本：

执行自己平台对应的修复脚本:

```
fix-feishu-mac.sh（linux/Mac 用户使用）

fix-feishu-win.bat（Win 用户双击执行）

fix-feishu-win.ps1（Win用户双击执行）
```

这里以 Mac 为例，如图所示： 1、执行修复脚本

![](assets/05-%E6%8E%A5%E5%85%A5%E9%A3%9E%E4%B9%A6%EF%BC%9A%E8%AF%A6%E7%BB%86%E9%85%8D%E7%BD%AE%E6%8C%87%E5%8D%97_GflKbkky5o.jpg)

## 三、常见问题

### Q1: 收不到飞书的消息推送？

**排查步骤 **：

1. 检查 Webhook 地址是否可访问

1. 验证 SSL 证书是否有效

1. 查看 OpenClaw 日志是否有接收记录

1. 确认事件订阅已正确配置

### Q2: 机器人无法发送消息？

**可能原因 **：

- 权限不足：检查是否申请了 `im:message:send_as_bot`

- 用户未激活：确保用户已加入企业

- 群组设置：检查群组是否禁用了机器人

## 四、本章检查点

完成本章后，请确认以下检查项都已通过：

### 基础检查

- [ ] 飞书应用已创建：在飞书开发者后台能看到应用
- [ ] 机器人能力已开启：应用详情页显示机器人已启用
- [ ] 权限已配置：已添加 im:message:send_as_bot 等必要权限
- [ ] 凭证已保存：已记录 App ID 和 App Secret
### 功能检查

- [ ] Webhook 可访问：配置的 URL 能从公网访问
- [ ] 事件订阅已配置：已添加 im.message.receive_v1 事件
- [ ] OpenClaw 已配置：~/.openclaw/openclaw.json 中包含飞书配置
- [ ] 应用已发布：版本审核已通过或自动通过
### 验证命令

```
# 检查配置是否正确
cat ~/.openclaw/openclaw.json | grep -A 5 feishu

# 检查 Gateway 状态
openclaw gateway status

# 查看最近的日志
openclaw logs --follow | grep feishu

# 测试 Webhook 连通性
curl -X POST https://your-domain.com/feishu/webhook \
  -H "Content-Type: application/json" \
  -d '{"test": true}'
```

### 常见问题快速排查

| 问题 | 检查项 |
|---|---|
| 收不到消息推送 | Webhook URL 是否可访问？SSL 证书是否有效？ |
| 机器人无法发送消息 | 是否申请了 `im:message:send_as_bot` 权限？ |
| 配置不生效 | Gateway 是否重启？配置文件格式是否正确？ |
| 应用审核不通过 | 应用描述是否清晰？是否涉及敏感功能？ |
