# 长期销售额 LTS

长期ROAS = LTS ÷ 广告花费

原理示意：LTS包含即时销售及未来价值估算，不能将不同归因口径的数据简单重复相加。这里的“首次”应按亚马逊的品牌新客和互动归因规则解释。

### 为什么这个变化重要？

过去，一个消费者点击广告、浏览商品，但没有立即购买，广告系统可能认为这次投入没有产生销售结果。

现在，如果这位消费者首次浏览你的品牌商品、搜索品牌词或者加入购物车，亚马逊可以参考历史上类似消费者的行为，估算这次互动在未来12个月可能带来的销售价值。

这意味着：

- 短期ROAS低，不一定代表广告毫无价值。
- 品牌词搜索、详情页浏览、加购等行为可以纳入广告价值评估。
- 品牌获客型广告与即时转化型广告可以使用不同的考核逻辑。
- 广告预算决策可以同时考虑短期利润与长期获客价值。

不过，LTS是估算的销售收入，不等于已到账销售额，更不等于利润，也不是保证未来一定发生的订单。

这一区分，对于你要开发的亚马逊广告健康诊断、利润模型和AI自动调价系统尤其重要。

## 三、LTS如何改变广告投放决策？

我建议将广告评价拆成三个层级，而不是用一个ACOS判断所有广告。

| 广告目标 | 核心指标                 | 决策重点        |
| ---- | -------------------- | ----------- |
| 即时利润 | ACOS、CPA、CVR、实际利润    | 控制成本，确保盈利   |
| 品牌获客 | NTB购买、获客成本、搜索与加购行为   | 发现真正带来新客的广告 |
| 长期增长 | LTS、LTS ROAS、实际销售兑现率 | 判断长期投资潜力    |

### 一个模拟案例

假设某品牌的广告活动取得以下结果：

广告投入

€100

14天归因销售额

€250

未来销售价值估算（示例）

€150

长期销售额 LTS

€400

即时 ROAS

# 2.50

对应即时ACOS 40%

长期 ROAS

# 4.00

包含未来预估价值

数字均为教学假设，并非真实亚马逊账户数据或官方计算权重。

如果你的产品广告前贡献毛利率只有30%，那€250实际销售产生的贡献只有€75，覆盖不了€100广告投入。

即使长期ROAS看起来提高到4.0，也不能立刻判定广告盈利，因为预计的未来销售尚未实现。

正确的运营方式：用实际利润决定短期生存，用LTS评估获客价值，用后续实际销售验证预测。

这里还可以增加一个重要指标：

\\[ \text{长期价值兑现率}=\frac{\text{同批顾客后续实际累计销售额}}{\text{对应口径的长期销售预测额}} \\]

需要使用一致的客户群组、观察期和归因口径。亚马逊新的 Accumulated Sales Report（累计销售报告）正支持将LTS预测与后续实际表现进行比较。

| `ntb_detail_views`        | 新客详情页浏览     | 购买兴趣   |
| `ntb_add_to_carts`        | 新客加购行为      | 高意向判断  |
| `ntb_purchases`           | 品牌新客购买量     | 获客效果   |
| `long_term_sales`         | 长期销售额       | 长期价值   |
| `lts_roas`                | 长期广告回报率     | 投资评估   |
| `contribution_margin`     | 广告前贡献毛利率    | 盈亏判断   |
| `attribution_model`       | 归因模型版本      | 历史口径对齐 |
| `attribution_window_days` | 归因窗口天数      | 防止混用数据 |
| `data_status`             | 实际值、预估值、缺失等 | 数据质量控制 |

数据取数要区分三种情况：

- Amazon Ads官方数据：优先调用统一报告或支持的广告接口，具体核实账户、站点、广告产品和字段权限。
- 卖家经营数据：通过SP-API、ERP和利润模块补充库存、价格、成本、退款、促销情况。
- 竞品数据：SIF、公开页面、第三方估算等只能构建外部信号，不能声称获得竞品真实LTS或私人广告账户数据。

现在公开资料确认LTS可在美国相关广告报告中查询，但我没有核实到所有LTS、四种新客行为都能在所有站点、所有广告层级通过API取得。因此开发时应该先做接口能力探测，不能直接假定关键词级、搜索词级都有这些字段。

### AI诊断规则应该如何升级？

| 诊断现象           | 旧广告模型   | 新广告模型建议             |
| -------------- | ------- | ------------------- |
| ACOS高，CVR低     | 直接降价或暂停 | 分析长期价值，再决定是否小预算保留   |
| ACOS高，NTB购买好   | 可能误判低效  | 作为获客广告单独考核          |
| ROAS高，主要依赖品牌词  | 判定为优质广告 | 进一步判断是否只在收割已有需求     |
| LTS高，实际利润低     | 可能忽略损益  | 保留观察，但限制可承受的亏损额度    |
| 品牌搜索增长，购买未增长   | 归因为无成交  | 检查Listing转化、价格和竞争情况 |
| 长期预测好，后续销售没有兑现 | 原系统难以发现 | 启动LTS预测偏差复盘         |

这里特别要避免用LTS直接驱动无人审核的加预算动作。

## 五、德国站和美国站分别怎么做？

德国站（当前优先建议）

先使用已开放的统一广告报告，建立关键词分层、广告五层结构、利润、库存和自然排名联动分析。由于官方LTS公告明确美国上线，不能默认德国账户已有完整LTS数据。可以先建立自己的长期价值估算模块，但必须和亚马逊官方LTS分开命名、分开展示。

美国站（适合测试新功能）

优先检查LTS与NTB报告权限。若账户满足条件，可选品牌代表性ASIN，对比传统SP/SB方案与全流域广告的实际销售、新客、LTS、利润和库存消耗。不要仅根据长期ROAS决定是否扩量。

## 六、建议按以下顺序落地

01

数据口径与接口验证

检查LTS、NTB、统一报告的可用范围，完成字段映射及归因口径记录

04

按Campaign与ASIN保存历史预测，持续比较后续销售兑现和投放效果
