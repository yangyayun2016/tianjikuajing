# 🗣️ Title Humanizer

> 让表达"说人话"——先搞清楚读者是谁、分享的契机是什么，再站在读者角度重新表达。

---

## 💡 为什么做这个

很多人做自媒体觉得自己"没有方向"，其实不是没有方向，是没有找到方法去**训练自己想清楚**。

这个工具会问你一些问题——读者是谁、他们关心什么、是什么让你想分享这件事。这些问题不是为了麻烦你，而是让你时刻记住：你在向谁表达，他们为什么要听你说。

AI可以帮你提效，但"想清楚给谁看"这件事，得你自己来。

---

## 🎯 解决什么问题

### 标题看不懂

很多标题让人看不懂，不是因为词太难，而是因为没有站在读者的角度去写。

**原标题：** 这个prompt太好用了直接出片

→ "prompt"是什么？"出片"是什么？普通读者完全看不懂。

**优化后：** Midjourney输入这句话，直接生成好看的图

→ 读者一眼知道在说什么、跟自己有没有关系。

### 不知道从哪个方向表达

很多时候卡住不是因为标题难写，而是更前一步的问题：

> 我有一件想说的事，但我为什么说这件事？从哪个角度说？说给谁听？

这些问题没想清楚，标题怎么改都不对，内容也很难往下写。

这个 skill 通过交互式提问，帮你一步步想清楚——读者是谁、他们关心什么、你的表达欲从哪里来。在这个过程中，你会发现更多可以展开的方向和角度，不只是得到一个标题，而是想清楚了"这件事值不值得发、怎么发最有意义"。

### 不只是标题

这个 skill 的核心逻辑是：**先搞清楚给谁看、为什么分享，再决定怎么表达。**

这套思路不只适用于标题，同样适用于：

- 💬 **话题选择**："我想发什么内容？"→ 先想清楚这件事对谁有意义、他们为什么关心，再决定发不发、怎么发
- 🔍 **内容角度**：同一件事可以从很多角度切入，skill 帮你找到最贴近读者的那个角度

你可以带着一个标题来，也可以带着一个想法或话题来——skill 都能帮你想清楚。

```

```

## 🚀 怎么用

在 Claude Code 中输入以下任一触发词即可：

- `标题优化`、`标题说人话`、`标题改写`、`取标题`、`写标题`
- `帮我看看这个标题`、`这个标题怎么样`
- 做自媒体内容需要起标题时
- 不知道该发什么话题，想理清楚给谁看

## 💬 使用案例

### 案例1：原标题方向不对，skill 帮你找到共鸣角度

**你给的：** 奔四中女学AI，自学是最蠢的

**skill 的判断：** "自学是最蠢的"说的是作者的结论，但读者正在自学——看到这句话第一反应是防御，不是共鸣。

**skill 问你：** 你想引出的是什么？读者看完希望他们想到什么？

**你说：** 想让他们知道，找一个靠谱的老师、体系化学习才是正路。

**skill 给的方向：** 不批评自学，而是说出读者自己的感受——"自学了很久，感觉在原地转圈"，让读者觉得"说的就是我"，再引出解法。

**✨ 最终标题：** 奔四中女学AI，自学真的不是最好的路

---

### 案例2：有想法但不知道往哪个方向说

**你给的：** 新手做自媒体，报了班也不知道怎么做

**skill 问你：** 你想让读者明白什么？

**你说：** 很多人上了课还是卡住，是因为在对照方法论做内容，而不是因为有了真实的感受才想分享。

**skill 的分析：** 读者花了钱、学了方法，还是出不来内容——他们怀疑的是自己，不是方法。你要给他们的是一个新视角：不是你不行，是因果搞反了。

**skill 给的三个方向：**
- 🎯 戳顾虑 → "报了班还是不知道发什么？可能是你把方法当起点了"
- 💭 说感受 → "做自媒体内容难产，不是你的问题，是顺序搞反了"
- 🔑 给出路 → "报了班还是没流量，因为你在用方法论找灵感"

**你在这个基础上提出自己的版本：** 自媒体报个班，你为什么还是没流量

→ skill 确认逻辑成立，直接用。✅

---

### 案例3：术语该留还是该换，skill 帮你判断

**你给的：** 这个workflow跑通了效率直接翻倍（面向效率工具爱好者）

**skill 问你：** 你的读者习惯叫它"workflow"还是"工作流"？

**你说：** 他们就叫workflow。

**skill 继续问：** 这个workflow是做什么的？标题里说清楚场景，读者才知道跟自己有没有关系。

**你说：** 知识管理。

**✨ 最终标题：** 知识管理workflow跑通了，效率直接翻倍

→ 保留了读者的叫法，补上了场景，读者一眼知道"这说的是我的事"。

## ⚙️ 工作流程

1. 🌱 **创作初心** — 先停下来想想：是什么让你想分享这件事？
2. 🔒 **锁定关键词** — 识别原标题中的人群/场景/领域词，生成时不会丢弃
3. ❓ **问清楚** — 确认读者是谁、关键信息是什么（一次一问）
4. 🔍 **读懂** — 分析作者想说什么、读者关心什么、会有什么感受
5. 🔤 **术语检查** — 基于读者判断哪些词他们能懂、习惯叫什么
6. 🤝 **自查+交流** — 跟用户确认分析结果
7. ✍️ **输出标题** — 从读者角度写标题，附自查表格
8. ✨ **优化（可选）** — 加情绪钩子、数字、身份代入等

---

## 📋 Skill 核心检查项

输出标题前，会对每个标题进行以下检查：

| 检查项 | 说明 |
|--------|------|
| 👁️ 读者能看懂每个词 | 有没有术语/行话读者不懂？ |
| 🙋 读者视角 | 说的是"这跟我有关"还是"我做了什么"？ |
| 📌 关键信息完整 | 工具名、场景、人群，该有的有吗？ |
| 🧩 前提条件完整 | 读者需要知道什么背景才能理解？ |
| 💎 读者能感知价值 | 标题传递的价值读者能感知吗？ |

## 🧠 个人风格档案（越用越准）

这个 skill 支持记录你的语言习惯，让生成的标题越来越接近你自己会说的话。

每次会话结束后，skill 会询问是否保存本次记录。**每积累5次，自动提示做一次风格汇总**，把规律提炼进 `user/style.md`。

- 📁 `user/title_sessions/` — 原始对话记录，含关键决策时刻，永久保留
- 📄 `user/style.md` — 提炼后的风格规律，每5次汇总覆盖更新

session 文件是标准 Markdown 格式，可以直接在 Obsidian 里打开或用 `[[]]` 链接引用，方便和其他创作笔记关联查看。

`user/` 文件夹已加入 `.gitignore`，不会被推送到 GitHub。

⚠️ **如果你 fork 或分享这个项目，请确认 `user/` 文件夹没有被包含在内。**

## 🔒 安全说明

**关于 AI 输出**
- AI 在遣词造句和语感把握上有局限，生成的标题仅供参考
- 最终发布的内容和标题，由创作者自行判断和负责
- 不建议不加修改直接使用 AI 输出的标题——换成你自己会说的话，往往更准

**关于个人数据**
- `user/` 文件夹存储的是你的个人语言习惯记录，属于私人数据
- 该文件夹已加入 `.gitignore`，正常操作不会上传到 GitHub
- fork 或分享项目前，请手动确认 `user/` 文件夹未被包含
- session 文件中记录了你的对话内容，请勿在公开环境中分享这些文件

**关于内容真实性**
- 这个 skill 帮助你更好地表达——但内容本身需要真实
- 标题承诺的内容，文章要能撑起来；不建议用这个工具制造夸大或误导性标题
